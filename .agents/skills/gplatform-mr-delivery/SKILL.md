# 主仓 MR 与回归交付

先读取 `../../../docs/mr-regression-workflow.md`。以实际受信控制器及固定输入为准，不把文档或 workflow 绿色等同于强制门禁已部署。

## 提交边界

- 核对各仓分支、HEAD、未提交改动、目标分支和本次授权；保留用户已有改动，必要时使用独立 worktree。
- 实际修改的仓库使用同名功能分支，父子依赖按完整 SHA 固定；按子到父提交推送，不直接写长期目标分支，不为无变更仓库创建空提交或空 MR。
- TestAssets 新增／修改资源只需推送到同名临时分支，本批不要求单独 MR，不自动送入 `main` 或平台分支。
- 主仓 MR 统一调度整套应用回归；App／源码库关联 MR 用于审查，不重复运行同一组合。
- 新 SDK 不是提交 MR 的前置依赖。主仓 MR 从完整源码构建，SDK 生产和更新属于回归通过后的 workflow 阶段。
- 提交、push、创建 MR、合并、发布及删分支按用户授权分别执行，不自动合并或发 Release。

## 执行顺序与资产

- 保留既有源码分支／SHA 选择入口；MR 使用主仓准确 head，App 和源码库从 gitlink 派生。
- Mac mini 固定使用 TestAssets `macmini`，Windows 固定使用 `windows`；prepare 各解析一次完整 SHA。不新增测试分支参数，不用 App 的 TestAssets pin 覆盖 Mac 平台资源。
- 新测试做本地必要验证即可提交临时分支；不要求先进入或先通过目标平台，不能为回归修改平台基准。
- 采用正式 preset 构建完整宿主 `gplatform_build`，复用 App 的平台执行函数与 `tools/run_acceptance.py --cases all`。保持 DB、截图、桌面和逐例判定，不另造执行器。
- 计划清单、实际完成清单及逐例证据必须完整。失败、空集合、缺项、取消、跳过、pending 或 not_verified 阻止 SDK 更新和放行。
- 两端回归全部通过后，调用既有 SDK 更新 workflow，使用同一源码 SHA及构建缓存，保留来源／载荷校验；同一 SDK 临时分支顺序更新 Mac 和 Windows 槽位，逐次核对旧 SHA。
- SDK 不自动回写正在验收的 MR 指针；输出 SDK SHA 和证据，后续独立消费及引用同步按对应任务处理，避免递归触发。

## 验证与报告

修改流程时只补本次链路缺口，保留独立 App SDK 消费构建和主仓手动观察入口，不顺手迁移旧原生测试或刷新标准。CI 测试放 App 的测试目录，业务／算法测试按其所有者维护，不新增宿主业务测试。

分别报告源码配置编译、真实程序和平台 Journal、SDK 导出、Git/LFS 交付、独立消费、安装与实机打印；未执行项不宣称通过。SDK 交付失败要与源码回归失败区分，不能重跑整批代替定位。远端排障按 AGENTS.md 通过 SSH 完成。

候选或输入变化后，旧结果不能放行新 head。分支保护、强制检查和最终合并权限单独核实；不声称跨仓原子合并，也不以手动跳过回归的构建冒充 MR 全量。
