# 切片开发

面向 App 保留源码的 `ThirdParty/OrcaSlicer` fork。先读其 `AGENTS.md`，核对 App、Orca 的 HEAD 与已有改动。路径相对 `APP_ROOT`，`SLICER_ROOT` 指该 Orca 目录。

## 算法库开发的优先流程

新增、提取或调整算法库能力，按以下顺序工作；已有缺陷先核对现有协议，避免为了修复再发明一套接口。

1. **先定义纯算法库契约**：明确能力边界、公开接口、入参/出参、配置、单位/坐标、资源与对象归属，以及相关错误、取消和结果生命周期。协议优先沿用当前 SDK 类型，不把 App DB、Qt/QML 或 GUI 单例作为算法输入。
2. **再查原始实现**：从对应原始分支/明确提交读取 Orca GUI，沿控件事件、参数处理、Plater/业务操作到内核和输出追踪。核对默认值、联动、校验、配置注入和资源；不能仅从当前无 GUI fork 推断原始行为。
3. **提取并复用**：优先直接调用已有内核；能力仍在 GUI 层时，提取相关代码，保留算法与业务语义，替换必要的 GUI 访问和上下文。按源码事实校准初步接口，不将尚未验证的设想冻结为协议。
4. **做必要协议封装**：转换输入、传递配置、调用原有能力、映射输出/诊断；App 再通过现有 Backend/Bridge 展示和调用。默认值、联动与校验在库内保持一致来源，不在 App 另写一份。
5. **验证复用与边界**：先检查库契约及与原始实现的一致性，再按任务验证 App 接线。仅在确认原始能力不足后扩展所需差异，说明新增代码与需求的关系。

具体协议要点、原始分支查阅方法与现有校准示例见 [原始能力提取与协议封装](references/original-code-and-protocol.md)。

不为封装引入新的 GUI 框架、全局活动状态、通用 RPC/序列化层或平行算法实现；新增状态、抽象和适配类需由当前需求证明必要。必要的提取和配套修改应完整，既有内核无关行为保持原有语义。

## 先分清错误在哪一层

```text
SlicingHandler → SliceSessionBuilder::capture/build → SlicingBackend
→ libslicer::Library::slice/slice_impl → Print::apply/validate/process/export_gcode
→ SDK ToolpathPreview → ToolpathPreviewPreparation/ToolpathResultPublication
→ SlicingPreviewBridge → 视口/导出/发送
```

配置未传入、坐标重复变换、运行库过期和预览解析问题，都需要先沿链路定位，不能直接归到填充算法。

## 按任务读取

- 库接口设计、GUI 原始调用链、代码提取复用与协议边界：[原始能力提取与协议封装](references/original-code-and-protocol.md)。
- 配置、材料映射、不可变请求、模型坐标、结果发布与校准：[应用与 SDK](references/application-and-sdk.md)。
- 内核阶段、连续纤维、覆盖余域、缓存失效与验证：[内核与纤维](references/kernel-and-fiber.md)。

## 定位算法缺陷与回归

涉及 bug 修复时同时应用 `gplatform-bugfix`，从合理性、架构、复杂度和范围判断方案。

1. 固定最小输入、最终配置、逻辑耗材槽与物理工具绑定、模型变换及目标层；性能任务保留同条件基线。
2. 找到差异首次出现的数据或阶段，核对实际读取的参数和归一化结果。
3. 在拥有该状态或几何的阶段修复；不通过最终 G-code 文本修改掩盖上游丢料或错误几何。
4. 新参数核对配置声明、预设归属、SDK 可见性、实际消费点和失效阶段；涉及 masks 或纤维时追加相应约束。
5. 构建正确来源的库并确认部署到实际程序，按改动选择内核/SDK/应用验证。

## 不变量

- 文档线程捕获 DB 状态，后台构建与切片使用值快照；不在后台从实时 Bridge 或 DocumentManager 补读输入。
- 保留 indexed mesh、部件角色、表面标签、耗材槽与 masks；不要以 STL 中转丢失语义。
- 明确长度/面积/速度单位与坐标系，使用现有缩放工具；`SCALING_FACTOR` 是运行时量。
- 保留最终纤维执行路径的方向、落纤、供料、CUT、被动沉积与非沉积尾段语义。
- 请求取消、替换或配置变更后，不发布旧结果或重新启用过期产物的导出/发送。

## 交付证据

新增或提取能力时说明库契约、原始 ref/提交与函数、复用部分、必要适配和相对原始行为的差异；小改动可在交付说明中记录，不强制额外文档。
完成前复查 diff 中的每个接口、状态、配置和包装层是否服务于当前需求；已有 SDK、库内上下文和原始算法能够承载的部分直接复用，不为协议封装引入第二份算法或不必要的资源/缓存体系。
说明影响阶段、有效输入/参数、构建库来源、执行测试与实际输出检查。普通模式与纤维模式共享代码变更时检查关闭纤维的行为。
真实应用验收使用 `gplatform-journal`；SDK 探针、几何检查和实机打印的结论分别说明。
